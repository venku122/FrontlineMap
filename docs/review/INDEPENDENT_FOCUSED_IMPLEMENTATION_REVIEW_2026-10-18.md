## Findings

### FI1 — High, corrected in inspected later source: native refresh event is not a session change

The first reviewed candidate subscribed `DynamicMap.onMapChanged` in `Plugin.cs:54`, and its handler at line 65 incremented session and unconditionally reset the controller/renderer. Native `DynamicMap.UpdateMap:820-843` invokes this event during ordinary map maintenance; `Update:867-873` calls it every approximately .1 real seconds. Therefore a healthy map could cancel/reallocate work ten times per second; a calculation longer than that interval would never complete, and existing output would clear repeatedly. Invariant: routine viewport/native marker refresh does not invalidate numerical session identity. This is source+target-contract evidence, not a measured launch outcome.

The coordinator accepted the finding. Later inspected `Plugin.cs:54-55,65` has no onMapChanged subscription/handler and retains per-LateUpdate actual geometry/admission checks. This addresses the identified source trigger. Required regression: host integration/wiring test with repeated native refresh notifications and unchanged signatures must preserve active and displayed work, while a real map identity change cancels it. A test of SetContext alone does not test whether Plugin is wired to the wrong event. Runtime lifecycle proof remains missing.

### FI2 — Medium, open at review snapshot: expired work monopolizes the scheduler

`src/Runtime/StepScheduler.cs:44-59` advances active work without checking `active.Snapshot.ExpiresAt`; pending requests are also started without expiry rejection. `OverlayController.cs:45,51,63` clears expired displayed output and rejects completed expired results, but does not abort already expired work. Counterexample: supported high-resolution/large-radius dense input takes 30 seconds with MaximumAge 15; from second 15 through second 30 the sole compute slot finishes an unusable result while recent pending snapshots wait. Repetition can mean no published field despite an apparently healthy scheduler. Invariant: expired calculations must stop consuming the only work slot, preserving the latest valid pending sample. Minimum correction: discard expired active/completed/pending work on the monotonic clock without dropping a newer valid pending request; continue or start that request. Add a synthetic clock case expiring active work mid-stamp and asserting latest valid pending progress and later publication. This follows directly from source; no runtime timing claim is made. It is falsified by an external expiry-cancellation path, which was absent in inspected Plugin/controller/scheduler.

### FI3 — Medium: screen-space raster stroke can disappear under zoom

Later `FieldClassifier.cs:47-50` computes a screen-distance estimate then marks only texel centers within LineWidthPixels/2. Removing the earlier adjacent-sign-crossing gate improves width behavior, but does not solve undersampling. Counterexample: a regular supported linear front passes exactly between two texture columns; at resolution 512 and projected width 3600 screen pixels, nearest samples are 3600/512/2 = 3.515625 pixels from the contour. A three-pixel stroke has half-width 1.5, so no texels become Front. Bilinear filtering cannot restore a gold line when no gold texels exist. Invariant: a claimed readable screen-space contour needs a declared sampling/zoom range or coverage strategy. Evidence: source and independently evaluated arithmetic; no actual target screenshot. Minimum correction: either document/restrict the supported width-to-resolution range and classify this as a blocked visual gate, or implement and test an antialias/coverage strategy with an explicit width-error tradeoff. Merely widening to at least one texel gives conservative visibility but sacrifices exact screen-space width. Include both an exactly sampled contour and an inter-texel contour at native-like zooms. Tests at 8/32/64 with convenient alignments do not establish arbitrary-zoom acceptance.

## Accepted source changes and limits

The adapter reads existing native marker display positions rather than allUnits/true position, rejects unresolved/mismatched viewer context and jamming, and uses explicit two-HQ support. This materially narrows the legacy information surface. Geometry derives from the native rectangle/display factor, rejects unknown Image/sprite/material forms, and parents raster output to the map rectangle. These are reasonable source choices; hierarchy/pivot/mask/calibration and actual marker behavior still require target tests. An unsupported binding currently hides quietly rather than explaining its reason; that is a usability limitation, not certified target incompatibility.

The controller stages invisible texture resources, revalidates after preparation using a fresh monotonic clock, refuses old identity/sequence/expiry, and releases discarded handles. The simple scalar oracle is independent of candidate footprint clipping; nonnegative F/E preserve balanced support and prevent single-sided opposing fronts. Movement arrows are absent. Later viewport repaint reuses the completed field and does not force a new scalar solve. These improvements are supported by source, without implying engine unload, resource counts, UI acceptance or fault recovery have been measured.

Every-LateUpdate native capture currently allocates/sorts marker observations and admission strings; allocations/clear/texture preparation remain indivisible. These are explicit unmeasured costs, so no optimization verdict is made. Before tuning, measure them separately and keep freshness/accepted observations fixed.
